## What MySurfLife Actually Is

Not a surf forecast site. The real product:

> Surfline tells you what the surf will be like.
> MySurfLife tells you what the surf will be like **for you**.

The core insight: experienced surfers synthesize storm tracking, buoy data,
model forecasts, tide charts, and years of local knowledge into a personal
prediction. No app assists with or learns from that process. MySurfLife does.

The moat is a feedback loop no other surf app has:
- User logs a session in 30 seconds
- App auto-populates actual buoy conditions from that time window (retroactively)
- Over time it learns the user's sweet spot at each spot
- Starts predicting session quality from personal history, not generic scores

## The Physics Engine — What We Built and Why

Three new modules implement the complete Stormsurf forecasting methodology.
These are validated against Stormsurf's published reference numbers.

### swell_physics.py
Implements the Stormsurf 12-step forecast methodology:
- `great_circle_nm(lat1, lon1, lat2, lon2)` — haversine distance in nautical miles
- `swell_arrivals(storm_positions, spot_lat, spot_lon)` — arrival time per period band
- `decay_size(storm_sea_ft, distance_nm)` — decayed swell height using empirical tables
- `speed_from_period(period_s)` — swell group velocity in knots

**Validation:** 2150nm (expected ~2153), 6.98ft decay (exact), 51.9hrs travel (expected ~52)

### swell_tables.py
- `swell_category(wvht_ft, period_s)` — Stormsurf Category 0-10 from buoy reading
- `surf_height_from_buoy(wvht_ft, period_s, size_bias)` — full face height estimation
- `estimate_sea_height(wind_kts, duration_hrs, fetch_nm)` — storm output estimation

**Why this matters:** A 6ft @ 7s swell is Category 1 (waist high). A 6ft @ 17s swell
is Category 4 (overhead to double). The old homemade multiplier didn't capture this.

### tides.py
- `fetch_tide_timeline(station_id, start, end)` — hourly predictions from NOAA CO-OPS
- `fetch_hilo(station_id, start, end)` — hi/lo events for session logging
- `register_routes(app)` — mounts endpoints on FastAPI app
- Fallback station map covers full CA coast + Hawaii

## The Three-Layer Sessions Schema

**Most important architectural decision of the project.**
Sessions have three separate conditions blocks — not one.

| Layer | What it is | Who writes it |
|---|---|---|
| `actual_*` | What NDBC buoys reported | Backend auto-pop job |
| `perceived_*` | What the surfer experienced | User (4 quick questions) |
| `forecast_*` | What the model predicted night before | Backend snapshot |

The delta between layers is the personalization engine:
- `actual_wvht_ft` vs `perceived_size` → spot amplification (canyon effect)
- `actual_mwd_deg` vs `perceived_dir_deg` → swell refraction at the break
- `perceived_quality` vs `actual_*` → personal preference signal

**Key schema decisions:**
- `perceived_size` uses surf vernacular (knee/waist/chest/head/overhead/doh/toh)
  NOT feet — surfers answer this consistently, feet answers are unreliable
- `perceived_quality` is 1-10 NOT 1-5 — finer granularity matters for ML
- Rating 1-10 intentional: more signal for preference modeling
- `user_spot_profiles` is computed, never edited directly by users
- Session log requires only 4 user inputs — 30 second target

## Known Bugs — Fix These Next

### BUG 1: Wind direction is 180° flipped 🔴 CRITICAL
**Evidence:** Surfline shows 3 kts NE offshore at Cardiff 8am.
Our Copilot showed 10 mph WNW (nearly opposite direction).
NE = offshore (good). WNW = onshore (bad). This changes the session call entirely.

**Root cause:** U/V to direction conversion using wrong convention in GRIB parser.

**Fix — one line:**
```python
# WRONG (direction wind blows TO):
direction = math.degrees(math.atan2(u, v)) % 360

# CORRECT (direction wind blows FROM — meteorological standard):
direction = (math.degrees(math.atan2(u, v)) + 180) % 360
```

**Verify:** After fix, cross-check against NDBC buoy wind direction for
buoy 46224 or 46225. Should agree within ~30° on steady-wind days.

### BUG 2: Swell components not decomposed 🟡
Surfline shows 3 separate swell trains (height + period + direction each).
Our Copilot shows a single blended number.

GFS-Wave GRIB2 has the data:
- Primary: `HTSGW`, `PERPW`, `DIRPW`
- Secondary: `SWELL`, `SWPER`, `SWDIR`

Need to surface both in tool responses as `swell_1` and `swell_2`.

**Surfline at 8am today for Cardiff:**
- 1.6ft @ 8s WNW 288°
- 1.3ft @ 11s SSW 201°
- 1.3ft @ 6s WSW 244°

**Our Copilot showed:** 3.8ft blended — overstated because it wasn't decomposing.

### BUG 3: Surf height overstated on small long-period swells 🟡
1ft of 18s energy does NOT produce 6ft surf. It improves shape but the
dominant short-period components control actual size.

**Fix:** Add minimum Hs floor to `swell_tables.surf_height_from_buoy()`:
```python
if wvht_ft < 1.5:
    return Category 1 maximum regardless of period
```

### BUG 4: Tide station verification for Cardiff 🟡
Surfline uses La Jolla Scripps Pier (station 9410230) for Cardiff.
Verify our `cardiff-reef` → `9410230` mapping matches.
Also verify negative tide values display correctly (-0.6ft at 8:55am today).

### BUG 5: Copilot asks user to look up storm data manually 🟡
When user mentions incoming swell, Copilot asks them to go to Stormsurf
and return with storm lat/lon coordinates. It should call `scan_active_storms`
automatically. That tool doesn't exist yet — it's the next tool to build.

## The Copilot — Current State + System Prompt Notes

### What it can do now (5 tools)
1. `get_spot_conditions` → current conditions at a spot
2. `get_conditions_window` → forecast for a time window
3. `get_buoy_history` → 12-48hr buoy trend
4. `compare_spots` → parallel fetch + ranked output
5. `rank_spots` → region-filtered scoring

### What it deflects (needs new tools)
- Tide questions → sends to external sites (need `get_tides` tool)
- Storm arrival questions → asks user to provide storm coords (need `scan_active_storms`)
- Swell arrival timing → can't calculate (need `calculate_swell_arrival`)

### System prompt rules to add/update
- "For current conditions always use live buoy readings. Model forecast is for
  future hours only. If model diverges from buoy at hour 0, explain why."
- "Never ask the user to look up storm coordinates — call scan_active_storms first."
- "When DPD at the buoy jumps 3+ seconds between readings, flag it as a swell
  arrival event."
- "Present swell components separately (swell_1, swell_2) not as a blended number."
- "When buoy Hs < 1.5ft, acknowledge that long-period energy exists but isn't
  producing significant surf yet — give the user a signal to watch for."
